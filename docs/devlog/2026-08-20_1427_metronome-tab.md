# Dev log — metronome tab

A fourth tab. Basics only this pass, per `docs/todo/TODO_METRONOME.md`.

## Why it is here at all
A plain metronome is the most commoditised app there is, and adds nothing over
the one already on a phone. What justifies it is sitting alongside the trainer,
tuner and drone — one thing on the stand — and composing with them: metronome
plus drone is long tones, in time, against a reference pitch.

## What it does
Tempo 30–250 with a slider, ±1 buttons and tap tempo; beats per bar 1–12 with
beat 1 pitched higher; a row of dots that lights the current beat; volume
independent of the drone; start/stop by button or space bar while the tab is
open.

## Timing: two clocks
The whole thing rests on not driving clicks from a timer.

Every click is scheduled ahead at an exact `AudioContext` time. A `setTimeout`
running every 25 ms only decides *when to top up the queue*, never when a click
sounds, and its jitter is absorbed by a 120 ms lookahead window. The audio clock
is sample-accurate, so the beat cannot drift no matter what the page is doing.

The beat indicator is driven from that same 25 ms wake-up rather than from
animation frames — this app has already been observed getting **zero** animation
frames while its tab was hidden, which would have frozen the display.

Tempo and bar length are read fresh on each scheduling pass, so a change takes
effect from the next beat without disturbing the ones already queued.

## Fixed while testing
The keydown handler called `e.target.matches(...)` unguarded. Real key presses
target an element so it never bit, but a synthetic event dispatched on
`document` threw, because `document` has no `matches`. Now guarded with an
`instanceof Element` check.

`button` joined the ignore list at the same time: after clicking Start the
button holds focus, and space would otherwise both re-click it and fire the
shortcut, toggling twice.

## Known limits
- **Background tabs.** Browsers throttle `setTimeout` to roughly once a second
  in a backgrounded tab, which is longer than the 120 ms lookahead, so the click
  queue would run dry and stutter. Widening the lookahead to survive it would
  make tempo changes laggy. Not worth it for an app you look at while playing;
  the UI says to keep the tab in front instead.
- **The microphone hears the click**, as with the drone. Untested against the
  trainer so far — a click is a broadband transient and YIN should reject it as
  unpitched, but that needs confirming on a real horn rather than assuming.

## Added before commit: accent toggle

**Accent beat 1** checkbox, on by default. Unchecked, every beat sounds
identical — same pitch and same level, since the accent carried both a higher
pitch and a louder click.

Setting beats per bar to 1 already produced an unaccented pulse, but it took the
bar-position dots away with it. The checkbox keeps the dots counting while
levelling the sound.

The first dot loses its marker when the accent is off, so the display never
promises an accent that won't sound.

| Check | Result |
| --- | --- |
| Accent on | `A...A...A`, first dot marked |
| Accent off | `.........`, one distinct pitch only, dot unmarked, 4 dots still counting |
| Accent on again | `A...A..` |
